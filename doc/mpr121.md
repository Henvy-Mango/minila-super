# MPR121 12 键模块：RMK 接入与调试

通过默认启用的 `mpr121` feature 接入 MINILA 的 RP2040 / RMK 固件，支持滑动音量、滑动后按住连发、
双击播放/暂停，以及长按检测。当前使用 defmt/RTT 提供触摸数据和手势日志，需通过调试探针读取。

## 样例里的按键顺序

依据提供的 `MPR121_Keypad_Example.pde`，其电话键盘字符与电极编号对应如下：

```text
电话键盘       电极编号（上 → 下）
 1  2  3         3   7  11
 4  5  6         2   6  10
 7  8  9         1   5   9
 *  0  #         0   4   8
```

代码保留真实电极编号，不把样例打印的电话字符当成编号。
三列电极的排列在 `src/touch/gesture.rs` 的 `KEYPAD_PATHS` 定义：

同一文件中的 `SWIPE_REVERSE_DIRECTION` 控制方向反转，当前配置为 `true`。
设为 `true` 后重新编译，上滑输出 `SlideDown` / 音量减，下滑输出 `SlideUp` / 音量加；
对应的按住连发方向也一起反转。双击、普通长按的行为及电极编号不变。
以下路径说明以未反转时（`false`）为准。

- 左列上滑：0 → 1 → 2 → 3；中列：4 → 5 → 6 → 7；右列：8 → 9 → 10 → 11。
- 反向为下滑；三列投影到同一纵向位置，允许换列及同一行跨列重叠。
- 例如 4＋8 算底行，5＋6 算第二、三行之间；按触及的行取中点，不按每行电极数量加权。
- 纵向移动一行即可触发一步，允许跳过中间行；同时触及相隔超过一行的电极仍会取消手势，直到释放。
- 双击支持上下、左右及斜向相邻位置，也支持相邻电极重叠。两次点击的全部电极须落在同一个 2×2 邻域内，单击无动作。
  例如先点 4 再点 5、先点 4 再点 8、两次都点 4＋5 可以；0 和 8 横向隔列，不会合并成双击。
- 同一行或相邻两行内的电极组合稳定保持 600 ms 触发 `LongPress`，之后每 350 ms 触发 `RepeatLongPress`；当前两者仅输出日志。
- 滑动后停在已触发滑动的位置上保持 600 ms，沿最后一次滑动方向每 350 ms 连发一格音量。
  日志用 `RepeatSlideUp` / `RepeatSlideDown` 区分连发与滑动；直接按住不调节音量。

模块面板标有 0–11，逐个触摸时可核对日志 `mask` 的对应位与实际标号是否一致。
若板子旋转安装或 PCB 连线与样例不同，只调整 `KEYPAD_PATHS`。

## 当前接线

引脚定义位于 `src/main.rs`。修改时同时保持 I2C 实例、合法 SDA/SCL 引脚和中断绑定一致。

| 模块 | RP2040 开发板 |
| --- | --- |
| VCC | 3.3 V |
| GND | GND |
| SDA | GP12（I2C0 SDA） |
| SCL | GP13（I2C0 SCL） |
| IRQ | GP14 |

使用 GPIO 编号，不是开发板排针的物理针脚号。供应商说明要求 3.3 V 供电。
确认 SDA/SCL/IRQ 的上拉在 3.3 V，模块若已带上拉通常无需再加；不要接 5 V 逻辑。
样例确认 ADDR 接地，因此使用 **7 位地址 0x5A**；0xB4/0xB5 是含读写位的表示，不能传给 Rust I2C API。

## 刷入固件并观察

编译与生成 UF2：

```sh
cargo make uf2
```

该任务内部已指定 release 构建，默认包含 MPR121；`cargo make uf2 --release` 也可以沿用。
确认接线后，将开发板进入 BOOTSEL 模式，把`target/minila-super-rmk.uf2` 拖入 RPI-RP2 磁盘。
这会替换开发板当前固件。此项目按常见 2 MB Flash RP2040 板配置，其他板需核对 `memory.x`。
当前固件未开启 USB 日志接口。接好 RP2040 调试探针后，可运行 `cargo run --release`，
由 `.cargo/config.toml` 配置的 `probe-rs run --chip RP2040` 刷写并读取 defmt/RTT 日志。
只复制 UF2 可以使用键盘功能，但不能通过 USB 串口读取这版触控日志。

输出包含：

```text
[...ms INFO] MPR121 initializing: addr=0x5A
[...ms INFO] MPR121 configured; checking environment, keep pads untouched
[...ms INFO] MPR121 checking: Settling, stable=0/1000 ms; gestures disabled
[...ms INFO] MPR121 ready: no touch and stable for 1000 ms; gestures enabled
[...ms INFO] MPR121 mask=0x800, filtered=[...], baseline=[...], delta=[...]
[...ms INFO] MPR121 gesture=SlideUp
[...ms INFO] MPR121 gesture=LongPress pads=[11]
```

`mask` 的 bit0–bit11 分别对应电极 0–11；baseline 已从 8 位寄存器左移两位，和 filtered 统一到 10 位尺度。
触摸通常使 filtered 低于 baseline。触摸状态变化时输出测量数据，识别到手势时另行输出手势日志。
采样与打印是分开的：100 kHz I2C 下，每轮的 8 ms 等待加上读取耗时约为 12–13 ms，
日志间隔不代表采样间隔。RMK 模式在状态不变时不周期打印测量值；长按和连发仍持续检测。
环境检查通过后的空闲状态只等 IRQ，没有周期性 I2C 读取。连接 RTT 日志读取工具后，触摸电极即可看到新数据。
由释放定时器确认的双击同样输出 `MPR121 gesture=DoubleTap`。
初始化后的第一组测量数据也会打印，包括零触摸状态。初始化日志只在启动/重试时输出，
可能在连接日志读取工具之前已发生；按下/松开时仍应有 mask 日志。
若没有启用 `mpr121` feature，构建脚本会明确警告固件没有触控输入；普通编译应保留
`[features]` 中的 `default = ["mpr121"]`。初始化失败则输出 `MPR121 fault=...` 并重试。

各字段含义：

- 日志时间前缀：自固件启动后的毫秒数，不是电脑时钟。
- `mask`：芯片报告的 12 路触摸状态，用十六进制显示；例如 `0x200` 表示只有第 9 位为 1。
- `pad`：当前触发的电极编号列表；例如 `[4, 8]` 表示同时触摸 4 和 8，`[]` 表示无触摸。
- 三个数组从左到右均对应电极 0–11；编号 9 对应数组的第 10 项。
- `filtered`：芯片滤波后的测量读数，不是电容量的 pF 数值。
- `baseline`：芯片跟踪的未触摸参考水平，随环境变化调整，不是固定常量。
- `delta`：`baseline - filtered`，单位为测量计数；正值表示读数低于基线。
  例如电极 9 的基线为 304、读数为 277，则变化量为 27。触摸通常产生较大的正值；
  小幅正负值可能来自噪声、基线跟踪和量化。保留负数，便于观察漂移。

当前驱动将触摸/释放阈值设为 15/10；触摸状态以芯片报告的 `mask` 为准。
`delta` 适合观察相对触摸信号，不能直接当作绝对电容量、按压力度或滑动毫米数。

推荐测试顺序：

1. 上电时不触摸；等待 USB 枚举和 `MPR121 ready` 日志，再触摸并松开，确认出现非零 mask 和 `mask=0x000`。
2. 逐个触摸 0–11，记录编号与布局，尤其检查 8–11 四路。
3. 沿任意一列连续滑动，先慢后快；确认方向与 `SlideUp` / `SlideDown` 一致。
4. 任一键连续轻点两次，应在第二次松开后产生一次 `DoubleTap`；单击不触发。
   保持单个电极 600 ms，应在仍按住时输出 `gesture=LongPress pads=[8]`（编号随电极变化）；
   继续保持每 350 ms 输出 `RepeatLongPress pads=[8]`，松手立即停止，且不触发双击。
5. 同一行横向滑动不调节音量；相邻跨列双击可播放/暂停；远距离双击及相隔多行同时触摸应不产生手势；采样期间断开并重新连接模块后检查错误报告和重试。
6. 松手后应停止触摸日志；下一次触摸能重新开始采样。IRQ 必须接到 GP14。
7. 滑动后停住约 600 ms，应开始每 350 ms 输出 `RepeatSlideUp` 或 `RepeatSlideDown`；松手立即停止。
   反向滑动应输出相反方向，并重新等待 600 ms 才开始反向连发。

当前按键板电极之间存在间隙。软件允许约 50 ms 短暂断触，若空隙导致松开更久，
一次滑动会分成不同接触。这需要实际数据来调节，不能由单元测试证明手感。
释放宽限从首次采到零触摸开始计时，包含 10 ms 去抖时间；第二次按下时也会检查
已经观察到的释放间隔，避免释放定时器尚未处理便把两次点击合并。

## 启动环境检查

启动流程为：芯片配置 → 环境检查 → `MPR121 ready` → 启用手势。
芯片必须先开启测量才能观察环境。环境检查期间会输出诊断数据，但不识别手势、不发送触控按键；
普通键盘任务仍正常运行。检查同样适用于通信故障后的重新初始化。

参数位于 `src/touch/environment.rs`：

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `STABLE_MS` | 1000 ms | 必须连续满足条件的时间 |
| `CHECK_INTERVAL_MS` | 20 ms | 检查阶段每次读取完成后的等待时间，实际间隔还包含 I2C 耗时 |
| `MAX_SAMPLE_GAP_MS` | 100 ms | 超过此采样间隔，重新累计稳定时间 |
| `MAX_FILTERED_SPAN` | 8 | 每路 filtered 在整个观察窗口内的最大值减最小值上限 |
| `MAX_BASELINE_SPAN` | 4 | 每路 baseline 在整个观察窗口内的最大值减最小值上限 |

此外，全部电极的 `mask` 必须为零，每路 `delta` 必须小于驱动的释放阈值（当前为 10）。
允许负 delta；不要求不同电极的绝对读数一致。窗口内的极差检查也能发现逐渐累积的漂移。
这些阈值是初始设置，需通过实体模块验证，不能视为所有触控板通用的值。

触摸、信号偏大、读数或基线波动、采样间隔过长，都会重新累计稳定时间，继续观察而不复位芯片。
`MPR121 checking` 最多每秒输出一次，原因含义如下：

- `Settling`：正在累计稳定时间。
- `Touch`：还有电极报告触摸。
- `SignalAboveRelease`：某路 delta 达到释放阈值。
- `FilteredUnstable` / `BaselineUnstable`：某路在窗口内波动超过上限。
- `SampleGap`：采样间隔超过允许值。

通信或芯片状态故障仍走原有重试流程，清除旧手势及稳定窗口，重新配置并检查。
只有连续稳定满 1 秒才打印 `MPR121 ready`，进入原有的空闲 IRQ 等待、接触时采样模式。
这会在原有配置耗时上至少增加约 1 秒；若基线仍在调整，会继续等待，没有超时后强行放行的逻辑。

此检查只在启动/故障重试时进行，不是运行中的持续环境监控。
它也无法可靠区分“干净且稳定”和“手指或异物已被吸收进基线后保持稳定”；上电时仍应保持电极干净、无触摸。

## 驱动及手势设置

`src/touch/driver.rs` 为独立寄存器驱动；`src/touch/mod.rs` 为 RMK custom input device；
`src/touch/processor.rs` 识别手势并输出 RMK KeyboardEvent。

- 软件复位并检查复位寄存器值；所有配置在 Stop Mode 写入，最后开启 12 路。
- 触摸/释放阈值采用样例的 15/10。AFE 为 16 μA、0.5 μs，SFI=4、ESI=4 ms，名义响应约 16 ms。
- 没有照抄旧样例的 `0x5D=0x04`：按所附正式数据手册，该值的 CDT 位为 0；本实现显式设为 `0x22`。
- IRQ 使用低电平等待，避免漏掉已经拉低的中断。每次读取 0x00/0x01 应答 IRQ。
- 芯片配置后先周期采样检查环境，通过检查才允许识别手势；接触期间每轮等待 8 ms 后读取（实际间隔还包含通信耗时）。
- 环境检查通过后，空闲只等 IRQ 低电平，不再有 20 ms 定时读取兜底；已拉低的 IRQ 也能唤醒。
- 零触摸采样后的 10、50、`DOUBLE_TAP_INTERVAL_MS + 1` ms 各有一次软件定时通知，用于去抖/重新启用、释放确认、点击过期。
  定时通知不访问 I2C；恢复触摸后取消剩余空闲定时通知。长期空闲时采集任务只有 IRQ 等待。
- IRQ 持续拉低时限制读取速率，避免忙循环。IRQ 未连接时，初始化后无法靠周期轮询发现触摸。
- I2C 有超时，读取时发现错误、过流或超范围会取消手势、释放虚拟键并重试初始化，失败时约每秒报告一次。
  空闲没有总线探测，所以此时拔掉模块可能不会立刻报告错误；重新上电后必要时重启开发板初始化模块。
- 手势状态去抖 10 ms；开始调音量只需移动一行，之后同方向每行一步，至少间隔 80 ms。
  反向滑动在满足移动距离和去抖后立即产生一步，并重置连发等待。
- `SWIPE_HOLD_DELAY_MS = 600`、`SWIPE_REPEAT_INTERVAL_MS = 350` 定义于 `src/touch/gesture.rs`。
  滑动后停在已触发滑动的位置（也可以是重叠位置）开始等待，再每 350 ms 连发一步；不会因为采样延迟集中补发多步。
  任意原始触摸状态变化立即取消当前连发计时；短暂断触恢复后也需重新等待 600 ms。
  连发在首次零触摸采样时停止，不等待 50 ms 释放宽限；相隔多行的无效触摸、通信错误也会停止。
- 点击持续 30–250 ms；`src/touch/gesture.rs` 的 `DOUBLE_TAP_INTERVAL_MS = 300` 配置第一次释放到第二次按下的最大间隔，修改后重新编译。
  点击过期的软件定时器也使用该配置；可设为 400 或 500 ms 增加容错。间隔小于 50 ms 的断触仍按同一次接触处理，不发送单击动作。
  两次点击及每次点击期间的稳定触摸轨迹合起来，最多跨相邻两行、相邻两列；已经触发滑动或长按的接触不参与双击。
- `LONG_PRESS_MS = 600` 定义于 `src/touch/gesture.rs`，从最后一次触摸位变化开始计时，在达到门槛后的采样确认长按。
  长按允许同一行或相邻两行的重叠电极，例如 4＋8、5＋6；先落在单电极、再覆盖第二个电极时重新计时。
  已触发滑动的接触不能转成长按；已触发长按后也不再触发滑动，直到完整释放。
  `LONG_PRESS_REPEAT_INTERVAL_MS = 350` 控制长按重复间隔；每次采样最多报告一次，不补发错过的次数。
  首次原始松手或触摸状态变化立即取消重复计时。小于 50 ms 的断触恢复后需重新停留 600 ms；
  已触发长按后，组合变化但纵向中点不变时重新等待 600 ms；
  去抖确认的纵向中点移动会终止本次长按连发，完整释放后才能开始下一次长按。
  `LongPress` 和 `RepeatLongPress` 事件携带完整 `mask`，日志以 `pads=[4, 8]` 等编号列表显示；没有默认按键映射。

滤波值用于调试，当前手势使用触摸位及电极位置。后续做连续铜箔滑条时可以增加电容权重插值。

## 接入完整 RMK 键盘

生成可刷入的 RMK + MPR121 固件（含 defmt/RTT 日志）：

```sh
cargo make uf2
```

产物为`target/minila-super-rmk.uf2`；使用 GP12/GP13/GP14 接线，
同时启用此项目的 MINILA 键盘矩阵和旋钮配置。进入 BOOTSEL 后复制 UF2 到 RPI-RP2。
`Cargo.toml` 中 `default = ["mpr121"]` 确保 build 和 objcopy 都启用触控代码，无需额外传 feature。

仅编译 ELF：

```sh
cargo build --release --bin minila-super-rmk
```

采用作者建议的 `#[Override(entry)]`，把输入设备和 processor 加入 `run_all!`。
保留矩阵、encoder_0、存储、USB host service、WPM 和 watchdog_runner。未启用 feature 时不占用 MPR121 GPIO。
RMK 宏在进入自定义入口前已启动硬件看门狗，必须将生成的 `watchdog_runner` 加入 `run_all!`。
RP2040 默认每 4 秒喂狗、8 秒超时；漏掉该任务会周期性复位，导致 USB 串口断开和终端退出。

当前 `Cargo.toml` 使用 RMK 默认的 `defmt` 后端，触控代码也使用 `defmt::info!` / `defmt::warn!`。
无需直接依赖 `log`；`.cargo/config.toml` 的 `DEFMT_LOG = "info"` 控制 defmt 日志等级。
普通 `Debug` 类型通过 `defmt::Debug2Format` 输出，因此仍能查看故障原因、手势和电极编号。

若以后切换 USB 日志，需要同步改动 RMK features 和触控日志调用：关闭 RMK 默认 features，
重新启用 `storage`、`vial`、`host_lock`、`watchdog` 和 `usb_log`，并将触控日志切换到 `log` 后端。
RMK 的 `defmt` 与 `log`/`usb_log` features 不能同时启用；仅添加 `log` 依赖不会把触控日志转发到 defmt。
参见 [RMK USB Logging](https://rmk.rs/docs/features/usb_logging.html)。

| 手势 | 虚拟矩阵位置 | 默认动作 |
| --- | --- | --- |
| SlideUp | (2,12) | AudioVolUp |
| SlideDown | (3,11) | AudioVolDown |
| DoubleTap | (4,4) | MediaPlayPause |
| RepeatSlideUp / RepeatSlideDown | (2,12) / (3,11) | AudioVolUp / AudioVolDown |
| LongPress { mask } / RepeatLongPress { mask } | 无 | 仅输出日志 |

使用没有实体按键的交点，并在 Vial 最下面增加一行。原 70 个实体键的映射不变。
若已有存储覆盖了新默认值，请在 Vial 里设置这三项及相关层，无需清空已有改键。
processor 独立计时释放按键，即使接下来 I2C 故障，也不会依赖新采样才能松开。
